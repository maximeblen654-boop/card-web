# 卡网部署与本机演练

这个私有仓库保存卡网的启动脚本、演练代码和 GitHub 云端构建流程。
商城核心使用 [Dujiao-Next v1.5.0](https://github.com/dujiao-next/dujiao-next/releases/tag/v1.5.0)，来源和版本固定在 `upstream.lock.json`。
GitHub 构建时直接取该固定版本的官方源码，前后端全部在 GitHub 的 Ubuntu 机器上编译，不占用本机的编译缓存。

## 在 GitHub 编译

进入仓库的 **Actions → Cloud build → Run workflow**。
完成后在该次运行的 **Artifacts → card-shop-linux-amd64** 下载 Linux 安装包、SHA256 和来源记录。产物保留 3 天，需要时可以重新构建。

这套流程生成包含顾客页面和管理后台的 Linux x86_64 程序，固定源码提交与依赖锁文件，不自动部署、不连接支付或卡台。自建程序标记为 `custom`，不会冒充官方发布的二进制，也不会开启官方发布版的自替换功能。
当前本机继续运行已校验的官方 Windows 成品；第一次云端构建不会替换它。
后续调整核心代码时，应将实际修改纳入源码仓库，并让构建指向已经审查的修改版本。

## 本机资料

`local-shop` 的启动、停止和演练脚本已保存。
本机商城依赖 `runtime` 私密配置、SQLite 数据库、Redis 数据，以及另行下载的官方 Windows 程序。它们不会上传 GitHub。
因此，**只克隆这个仓库不能恢复商品、卡密和订单**；这些数据需要独立、受保护的备份。

本机演练仍使用 `http://127.0.0.1:18080`，模拟收银台使用 `http://127.0.0.1:18081`。
历史演练脚本会修改测试商城数据，且部分对应启用验证码之前的配置；不要把它们直接用于正式商城或当作当前环境已经完整验收的证明。

## 本地与 GitHub 分工

- 本地：保留可编辑脚本、当前演练程序、配置、订单与卡密。
- GitHub：保存经过筛选的代码、版本记录和云端编译流程。
- 正式服务器：购买后部署商城，另行配置域名、防护、支付和供货。

GitHub 代码托管及云端编译不能替代商城服务器。工作流使用标准 GitHub 托管 Ubuntu 机器，运行用量由账户的 Actions 额度及计费设置决定。
